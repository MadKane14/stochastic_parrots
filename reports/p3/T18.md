Status: running (Kaggle). Verdict: pending.

## Setup
- **Tool:** `exploration/p3/dense_cv_group_prune.py` runs p2's `exploration/p2/dense_cv_group.py` **unchanged**, and p2's
  JSON is written as usual. p1's `dense_cv.build_pairs` / `oof_scores` are wrapped, not modified, so the same run's
  pairs, out-of-fold final scores and folds stay in memory.
- **Pruning is evaluated out of fold, like `Pipeline._prune`:**
  - The configured stage-1 scorer (`prune.scorer`, on `prune.features` only) is fitted on each fold's training
    candidates and scores the held-out fold.
  - Per S1, keep score ≥ `min_score`, best first, at most `max_per_s1`.
  - The same final-model OOF scores are decided on the survivors (p1_assign rule), so pruned true pairs count as misses.
- **Configs (same commit):**
  - `configs/exp/p1/T13_sub4.yaml` (= submission #4, LB 0.978)
  - `configs/exp/p3/T15_sub5.yaml` (= T13_sub4 + T15_final blocking; prune also sees blk_1/blk_2)
- **Group:** India (evaluation choice as in p2's tool; blocking, IDF and density of the group are exact).
- **Embeddings:** `p1_e5` (pretrained multilingual-e5-small, fields name + full) for the India group's train records,
  precomputed on a Kaggle GPU kernel (`grootji/ber-p3-t18emb`, `exploration/p3/e5_group.py`).
  - Same `p1_e5` code as the feature set: the files are keyed by the dataset fingerprint, which is the one the dense
    run looks up.
  - The CPU kernels verify the files before starting.
- **Machines:** two Kaggle CPU kernels of the same type (4 vCPU, 30 GiB, no swap), one per config, in parallel:
  `grootji/ber-p3-t18a` (T13_sub4) and `grootji/ber-p3-t18b` (T15_sub5). F0.5 is deterministic given data, config
  and seeds; runtime and peak RSS are per kernel.
