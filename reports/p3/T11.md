## Why these changes (evidence already on the repo)
- **Right records with an empty address are the worst subset after p2_translit.** p2's full-density eval of T04_d
  (= T09_tr's normalizer, qfrac 0.1, `exploration/p2/kaggle_logs/blk2_02_D.log` on w/p2) gives recall_empty_addr
  **0.8833**. The other subsets score higher: non-Latin name 0.9778, web name 0.9849, letter-run 0.9946.
  - Empty addresses are 3.3% of S2/S3 records (`exploration/p1/eda_out.md` Q5) but 22% of best.yaml's misses (I-12).
  - Mechanism: p1_compound normalizes each S1 over all its (long) address features. A name-only right record can
    only reach its S1 with a diluted cosine, so it loses the top-k race against same-address neighbours.
- **Candidate count now matters (D13).** A channel must add few candidates. An index over only the address-less
  right records is small, so its reverse list costs ~0.03 × k_rev cands/S1.

## What I did
- `p3_chargram` gains two options (still one file, `src/ber/blocking/p3_chargram.py`):
  - `words`: adds name word unigrams and unordered word pairs, p1_compound tokenization, to the char 3/4-gram bag.
  - `right_max_addr_tokens`: indexes only right records whose address has ≤ N tokens.
  - With N = 0 and no `addr_field`, this is the **empty-address channel**: S1 rows are normalized over name features
    only and compete only against address-less right records. It runs forward top-k and reverse top-k_rev.
- Configs, all inheriting `p1/T09_tr.yaml`:
  - `T11_base`: T09_tr unchanged.
  - `T11_e`: + empty-address channel, k=2, k_rev=5.
  - `T11_e10`: k_rev=10.
  - `T11_e4`: addresses ≤ 4 tokens.
  - `T11_ca`: T05's name-gram + address channel on T09_tr.
  - `T11_eca`: both channels.
- New eval tool `exploration/p3/blk_dense.py` fixes three problems with blk_eval/blk_union for this task:
  1. `--dense` keeps **all** S1, so reverse retrieval is at true density. qfrac 0.1 had inflated p1_compound to
     143 cands/S1 (T05 report). Metrics are scored on the query S1 only.
  2. Label-fitted normalizers are fitted on non-query labels. At plain `--qfrac 1`, blk_eval fits p2_translit
     **without labels**, so there is no token map at all.
  3. It runs one subprocess per (blocker, country-string group) and reads a slim pyarrow subset, so it fits Kaggle's
     30 GB. The old load alone peaked at 17 GB.
  - It also reports recall on subsets (right address empty, right name non-ASCII, no shared name token) and each
    blocker's unique contribution. The per-S1 cap emulates `Pipeline._block`.
- Local plumbing check on a 40k-S1 real-data sample (low density, **not evidence**):
  - Full recall 0.9978 → 0.9985 at +1.6 cands/S1.
  - Empty-address pairs 0.9793 → 0.9951.
  - The empty bucket is the only one clearly below the rest (0.975 vs ≥ 0.996).
