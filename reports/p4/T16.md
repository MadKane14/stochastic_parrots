## b) Cross-fitting (stretch) — code ready (`94aa3f6`)
- `p4_e5cf` (`src/ber/features/p4_e5cf.py`): 2 fine-tuned models. S1 fold = `int(unit_hash(s1_id, 777) * 2)` on the
  **entity id**, not the row position. That keeps the same fold in every dataset (train, val splits, test), and
  honesty only needs "no pair is embedded by a model that saw its S1", not alignment with dense_cv's GBDT folds.
  A pair of an S1 in fold f uses model 1−f, the same rule on train and test. It reuses p1_e5's memmaps (one per
  model) and emits the same 10 columns as p1_e5 (`f_p4_e5cf_*`). A synthetic test passes.
- Train the two models with `e5_finetune.py --split full+fold2:0` / `full+fold2:1` (v1 recipe).
- `configs/exp/p4/T16_cf.yaml` = T10_e5 with p1_e5 → p4_e5cf (`${BER_ARTIFACTS}/models/ft_h{0,1}`).
- T16b (Kaggle, ~19:30) checks it on val_v1@0.1: pretrained vs naive fine-tuned vs cross-fitted, same base config.
  If naive ≈ cross-fitted, p1 can skip cross-fitting overnight and use `ft_full` (1 model, half the embedding work).
