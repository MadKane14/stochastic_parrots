# T16 report — p4 (final, Sat 19:50)

Status: done (Kaggle part). Decision runs are on phoenix (p1).
Verdict: **Use the v1 fine-tuning recipe, a single model on all train pairs (`ft_full`).** On the unseen-country
proxy it beats every other recipe tried. Cross-fitting is not needed: it ties naive fine-tuning.

## Final command (p1, phoenix, overnight)
```bash
python exploration/p4/e5_finetune.py --split full --out $BER_ARTIFACTS/models/ft_full --n 400000   # ~12 min on a T4
# then p1_e5 with `model: <abs>/ft_full` (fields [name, full]) for train + test embeddings
```
Defaults = the v1 recipe: `--neg address --batch 192 --lr 2e-5 --tau 0.05 --max-length 64 --epochs 1 --seed 0`.
The unseen-country check on phoenix (India fold of dense LOCO) uses the same recipe with `--split xc_India`
(`exploration/p4/T12_ft_phoenix.sh`).

**Finding:** negatives mined from the training country's blocker candidates make the embedder learn that
country's confusions and **transfer worse**. More of them is worse (v2b < v2), and mixing does not help
(v3 is lowest). In-country, v2 was slightly better than v1 (val_v1@0.1 harness 0.9910 vs 0.9899, CIs touch;
intrinsic name+addr AP 0.9978 vs 0.9961). France is unseen, so v1 is the robust choice.

## b) Cross-fitting — not needed (T16b)
val_v1@0.1, same base config (best.yaml + string_sims + E5 name/full with rank/gap), commit `d62ddbe`:

| E5 feature | F0.5 [CI95] | scorer AUC / AP | run_id |

Naive ≈ cross-fitted: fitting the GBDT on pairs the embedder was trained on does not hurt. **A single `ft_full` is
enough**, at half the embedding work. Cross-fitting remains available for an honest hash-fold dense-CV number:
`p4_e5cf` (`src/ber/features/p4_e5cf.py`, fold = `int(unit_hash(s1_id, 777) * 2)` by entity id, so it is
stable across datasets), `configs/exp/p4/T16_cf.yaml`, and models from `e5_finetune.py --split full+fold2:{0,1}`.

wall on 2× T4 (`exploration/p4/T12/e5_embed_all_*.json`); p1 reports 15k names/s on an A4000.
