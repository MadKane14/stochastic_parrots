## Caveat + optional hardening (not required by this evidence)
In deterministic mode torch warns once: "Memory Efficient attention defaults to a non-deterministic algorithm" (the
fused SDPA backward). It produced identical results here (same GPU type, 104 steps), but bit-identity is not
guaranteed across GPU models (T4 vs A4000) or for the full 2,083-step run. Smallest hardening, if the lead wants
bit-reproducibility to be *guaranteed* on one machine (cost: slower attention, ~+10–20% training time):
```diff
--- a/code/business_entity_resolution/src/e5_finetune.py
+++ b/code/business_entity_resolution/src/e5_finetune.py
@@ def main():
     import torch
     from transformers import AutoModel, AutoTokenizer
     torch.manual_seed(a.seed)
+    torch.use_deterministic_algorithms(True, warn_only=True)          # + env CUBLAS_WORKSPACE_CONFIG=:4096:8
@@
-    model = AutoModel.from_pretrained(a.model).to(dev).train()
+    model = AutoModel.from_pretrained(a.model, attn_implementation="eager").to(dev).train()   # deterministic attention
```
Across different GPU models exact equality is not expected with any setting (different kernels); what matters for the
organizers is that the README states the command, seed and that results match to float tolerance.
