## What I did
- New FeatureSet `p4_e5` (`src/ber/features/p4_e5.py`): `intfloat/multilingual-e5-small` embeddings of the raw
  name, address and "name, address" texts (`"query: "` prefix, mean pooling, L2-normalised, fp16, max 64 tokens).
  Each unique text is embedded once and cached as `$BER_ARTIFACTS/emb/<model>/<field>_ml64/shard_*.npz`, keyed by a
  64-bit text hash. Output: 3 cosines `f_p4_e5_{name,addr,full}_cos`, NaN when either text is empty.
  With `group_feats: true` it also outputs, per field, the gap to the best cosine within the S1 entity and the rank
  (`_gap`, `_rank`), giving 9 columns.
- Configs `configs/exp/p4/T06_{base,e5,e5g}.yaml` (base = best.yaml, so the baseline shares a commit with the
  other two). Runs were made in a Kaggle GPU batch kernel (setup in `reports/p4/T01.md`).
- Throughput benchmark `exploration/p4/e5_throughput.py`, which embeds a 200k-record uniform sample of all train+test
  source files. Output is in `exploration/p4/e5_throughput_out.md`.

## What I learned
- **E5 features help most where string similarity is weakest.** India F0.5 +0.0044 on val_v1@0.1 (0.97778 → 0.98221)
  vs US +0.0003, and +0.017 on the unseen-country proxy xc_India@0.1 (0.9239 → 0.9413), mostly from recall
  (0.873 → 0.909). Pairs with a native-script name are 13.9% of all true pairs (p2's `exploration/p2/translit_map_out.md`,
  on `w/p2`). They share no tokens with the Latin S1 name, and a multilingual encoder puts both forms close together.
  (runs above)
- **Group-relative E5 features add a further +0.0014 (val) / +0.0058 (xc_India)**, and xc_India AUC goes
  0.9816 → 0.9970. Part of this gain is probably the group-relative idea in general, which p1 is adding for string
  features in T03, so it has to be re-measured on top of T03. (runs `…8eacdf` vs `…b35e9f`)
- Blocking is identical in all runs (oracle F0.5 0.9986 / 0.9942, 33.5 / 33.4 cands/S1), so the whole gain is from
  the scorer.
- **Throughput (T4, fp16, batch 512), from `exploration/p4/e5_throughput_out.md`:** name 9,605 texts/s,
  address 6,613/s, name+address 5,080/s. All 24.2M train+test records × 3 fields = **~3.0 GPU-hours on one T4**
  (upper bound, no deduplication). Test alone (11.7M records) is ~1.5 h on one T4 and less on phoenix's A4000s.
  Peak GPU memory 0.52 GiB. The harness runs match: the val_v1@0.1 e5 run embedded 2.7M unique texts at
  5.0–8.8k/s (`exploration/p4/kaggle/logs_v2/T06_e5.log`).
- The xc splits share records with val_v1, so the cache made the other runs cheap: `features:p4_e5` took 642 s on
  a cold cache and ~117 s warm.

## Surprises / bugs / data issues
- **Overnight full embedding was not done, because of storage.** 24.2M × 384 × fp16 = 18.6 GB per field, 56 GB for
  3 fields, but Kaggle keeps at most 20 GB of output. Recomputing the embeddings inside the pipeline is cheap instead
  (~1.5 h for test on one T4; see above).
- Kaggle image conflict: the pinned `torch==2.8.0` breaks the image's `torchvision` (`operator torchvision::nms
  does not exist`), and then `transformers` cannot import `BertModel`. Fixed by uninstalling torchvision/torchaudio
  in the runner. Kernel v1 therefore has base runs only; kernel v2 has the rest on the same commit.
  Logs are in `exploration/p4/kaggle/logs_v{1,2}/`.
- Only the first smoke run embedded names slowly (681/s, includes model download + CUDA warm-up).

## Proposed next steps (ranked, with expected gain)
1. **Put `p4_e5` (e5g variant) into the matcher once p1's T03 lands**, and re-run T06_base vs T06_e5g on that
   commit. Expected: +0.002–0.003 val_v1@0.1, +0.02 xc_India@0.1 (less if T03's group features overlap). The test
   run costs ~1.5 GPU-hours of embedding.
2. **Field ablation** (name / addr / full): "full" is 43% of the embedding cost. Dropping a field that adds nothing
   cuts test-time cost.
3. **Contrastive fine-tuning of e5-small on train true pairs** (planned for next round). Hard negatives would come
   from the blocker's top candidates, and the fitted model would be judged on xc_India so we can see if it
   generalises to an unseen country. Expected: the largest further gain on cross-script and typo pairs.
4. **An E5 ANN blocking channel** (with p3): kNN on the "full" embeddings within country-string groups could recover
   the 29% of blocker misses whose S2/S3 name is non-Latin (I-12), which string keys cannot reach. It needs the
   full-density `blk_eval.py`, which does not fit on Kaggle (31 GB).
