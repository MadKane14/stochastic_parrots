## Recipe (`exploration/p4/e5_finetune.py`)
- One random true match per S1 entity (400k), text "query: " + field, fields alternating per batch (name,
  name+address). Same encoder and pooling as `p4_e5`/`p1_e5`.
- Hard negative: an S2/S3 record with the same country and the same cleaned address that is not a match. Only 3–4% of
  triples found one (13,150 / 17,192), so the rest are random same-country records. Improving this with blocker
  candidates as negatives is the obvious next step.
- InfoNCE over [positives; negatives] of the batch, τ 0.05, AdamW lr 2e-5 (5% warm-up, linear decay), fp16 autocast,
  1 epoch. Saved as fp16 `save_pretrained` (~235 MB), loadable as `p1_e5` `model: <dir>`.
- Rules: provided train data only, MIT base model, 117.65M params (fine-tuning adds none), runs offline, no country
  logic. The fine-tuned weights must ship with (or be reproduced by) the final package: 1 command, ~12 min on a T4.
