## Plan (written before any evaluation; variants and thresholds fixed up front)

**Goal (T04):** raise full-density pair recall of `best.yaml`'s blocker (`p1_compound` k=30, k_rev=3, max_df=1000;
0.9699 at `--qfrac 1`, `exploration/p1/blk_eval_out.md` run 20:51) by ≥ +0.005 through normalization only, with the
largest gain on the pairs p1 found hardest (I-12: 29% of misses have a non-Latin S2/S3 name, web-style names,
typo'd names without address).

**Why normalization is the lever (from p1's evidence):** `p1_compound` scores IDF cosine over tokens and token pairs
within country-string groups. A native-script name shares *zero* tokens with its Latin S1 name, so the only thing
that can retrieve it is the address; a web name (`supremepackaging`) is one high-IDF token that matches nothing.
Turning these into the tokens S1 uses makes every existing channel (U_name, P_name, NN) work for them, without
adding candidates (no extra blocker, cands/S1 unchanged by construction).

**Method (all learned from train, script-agnostic, no country branches, no hand-written dictionaries):**
1. *Learned token map* native → Latin from true pairs, word alignment by **competitive linking** (Melamed 2000):
   Dice co-occurrence, then one-to-one linking inside each pair so `प्राइवेट` → private (not limited). Same idea as
   transliteration mining from word-aligned parallel data (Aksharantar, 2022) — our true pairs are the parallel data.
   Keep a mapping if support ≥ 3 and precision ≥ 0.5 (fixed a priori, not tuned).
2. *Script folding*: Brahmic scripts share one Unicode layout (Unicode ch. 12 / ISCII), so each letter is folded to
   the Devanagari letter with the same Unicode character name — pools evidence across Bengali/Odia/Kannada/Tamil/…
   without any table. Any-script decimal digits → ASCII.
3. *Web names*: strip a trailing web suffix (`.com`, `.Com`, `.co.in`; ≥ 4 word chars before the dot, suffix not a
   legal form) and `www.`; split concatenations by unigram Viterbi segmentation over a vocabulary counted from names
   (train + target records, no labels → `transductive = True`); 1/0 → l/o only if the variant is a known word.
4. *Initial runs*: `p l l c` → `pllc`, `m w jackson` → `mw jackson` (applied to both sides identically).

**Pre-registered variants** (`configs/exp/p2/`): A = all steps, replace mode (main); B = A in append mode (T04 asks
for both); C = A with only the learned maps (isolates cross-script); D = A without script folding (pooling gain).
Selection rule declared up front: best = highest full-density pair recall; ties (< 0.001) → the simpler variant.

**Evaluation protocol / anti-overfitting:**
- Full-density blocking: all 10.3M S2/S3 records, 10% of S1 as queries (`--qfrac 0.1`); the normalizer is fitted
  ONLY on true pairs of the other 90% of S1 (`fit_gt`) → the queries' pairs never inform the map.
  Script `exploration/p2/blk_eval_p2.py` = p1's protocol and metric code (imported) + recall on raw-defined subsets
  (non-Latin name / web name / empty address / letter runs) so every variant is judged on the same pairs.
- Map quality on held-out pairs: `exploration/p2/translit_map_report.py` (coverage + accuracy of mappings on the
  10% held-out S1 pairs; test coverage reported as a diagnostic only, never used for a decision).
- End-to-end: harness `val_v1@0.1` and `xc_India@0.1` for baseline vs best 2 variants (the map is fitted on the
  split's train side only; xc_India shows what happens when the map has no data for a country — the France proxy).
- Nothing is tuned on these evaluations; all variants tried are reported.

## What I learned
- The normalizer lifts full-density pair recall 0.9805 → 0.9869 with the same number of candidates; the gain is where
  predicted: non-Latin names 0.918 → 0.978, web-style names 0.950 → 0.985. (`blk_eval_json/`)
- Ablation C (maps only): the cross-script map alone gives +0.0039; web-name/initials steps add the other +0.0025
  (web-name recall is unchanged in C, 0.9500, and jumps to 0.9849 in A/D).
- End to end, val_v1@0.1 F0.5 +0.0040 (A) / +0.0036 (D) over the same-machine baseline, CIs disjoint; India
  0.9778 → 0.987; US unchanged (tie). Both precision and recall rise, and singleton accuracy rises (0.974 → 0.978–0.981).
- Unseen-country proxy xc_India@0.1: +0.004 (0.92393 → 0.92789, CIs disjoint) even though the map learns nothing from a
  US-only train side → the generic steps (web names, 1/0 variants, initials) transfer across countries — relevant for France.
- Append vs replace (A vs B): identical recall; replace keeps names shorter → preferred.
- Non-Latin names are more common than p1's miss profile suggests: 13.89% of all true pairs have a native-script
  S2/S3 name (1.06M pairs); the current blocker still finds most of them via the address (29% of misses).
- A token map learned purely from our own pairs covers 98.7% of held-out native-name tokens with 96.3% accuracy
  and 95.0% of test native-name tokens → cross-script names can use the name channels. (`translit_map_out.md`)
- Script folding does NOT help: coverage/accuracy 0.9871/0.9630 folded vs 0.9877/0.9643 unfolded (tie) — every
  script has enough pairs on its own. By the declared tie rule the simpler D (no folding) is preferred unless
  blocking recall says otherwise. (`translit_map_out.md` vs `translit_map_out_nofold.md`)
- Address native tokens are only 17 state names; the map gets them all right, but one-to-one linking keeps one word of
  two-word states (`तमिऴ्नाटु` → nadu, `पश्चिमबङ्ग` → bengal).

## Surprises / bugs / data issues
- **Compute:** evaluations ran on Kaggle (private datasets `ber-train-p2` = train TSVs, `ber-code-p2` = git bundle;
  no internet). Kaggle's preinstalled numpy 2.0.2 / scipy 1.16.3 / scikit-learn 1.6.1 / pyarrow 24.0.0 differ from the
  pins (Python 3.12); both reproduction checks (p1 blocking numbers, baseline F0.5 0.98428 vs p1's 0.9843) match exactly.
  Peak RSS of the blocking eval with p2_translit: 27–28 GB (baseline 26.2 GB). Kernel logs: `exploration/p2/kaggle_logs/`.
- Normalization cost: 725–755 s for 12.5M records in blk_eval (basic: ~150 s); in the harness 47 s vs 38 s.
- Diagnostic seen in every harness JSON (not my task, for p1): the plain threshold curve peaks at 0.6, not 0.5.
- Web-style names are ~4% of S2/S3 (~200k per source, e.g. `pediatricmedicine.com`, `Dr dreammarketing.Com`).
- Segmentation needed constraints: with 2-letter pieces allowed it shredded typos (`coniultancy` → `co ni ul tan
  cy`). Fixed from a qualitative look at 25 random TRAIN names (before any evaluation): pieces ≥ 3 chars; non-web
  tokens only split into 2 words of ≥ 4 chars.
- Bug fixed: segmentation counts were double-counted when fit() and transform() saw the same records (train side
  vs val/test inconsistent) → per-token max; regression test `test_subset_consistency`.
- First map implementation (object DataFrames, ~20M within-pair edges) was OOM-killed at 6.7 GB; rewritten with
  integer codes + numpy (peak 5.4 GB for the whole report).
- Tied associations (`प्रा`/`लि` always co-occur with pvt/ltd) are broken by first occurrence; either way the bag
  of tokens {pvt, ltd} is identical, so blocking is unaffected.
