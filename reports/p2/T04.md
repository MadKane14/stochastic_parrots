## Plan (written before any evaluation; variants and thresholds fixed up front)

**Goal (T04):** raise full-density pair recall of `best.yaml`'s blocker (`p1_compound` k=30, k_rev=3, max_df=1000;
0.9699 at `--qfrac 1`, `exploration/p1/blk_eval_out.md` run 20:51) by ≥ +0.005 through normalization only, with the
largest gain on the pairs p1 found hardest (I-12: 29% of misses have a non-Latin S2/S3 name, web-style names,
typo'd names without address).

**Why normalization is the lever (from p1's evidence):** `p1_compound` scores IDF cosine over tokens and token pairs
within country-string groups. A native-script name shares *zero* tokens with its Latin S1 name, so the only thing
that can retrieve it is the address; a web name (`supremepackaging`) is one high-IDF token that matches nothing.
Turning these into the tokens S1 uses makes every existing channel (U_name, P_name, NN) work for them, without
adding candidates (no extra blocker, cands/S1 unchanged by construction).

**Method (all learned from train, script-agnostic, no country branches, no hand-written dictionaries):**
1. *Learned token map* native → Latin from true pairs, word alignment by **competitive linking** (Melamed 2000):
   Dice co-occurrence, then one-to-one linking inside each pair so `प्राइवेट` → private (not limited). Same idea as
   transliteration mining from word-aligned parallel data (Aksharantar, 2022) — our true pairs are the parallel data.
   Keep a mapping if support ≥ 3 and precision ≥ 0.5 (fixed a priori, not tuned).
2. *Script folding*: Brahmic scripts share one Unicode layout (Unicode ch. 12 / ISCII), so each letter is folded to
   the Devanagari letter with the same Unicode character name — pools evidence across Bengali/Odia/Kannada/Tamil/…
   without any table. Any-script decimal digits → ASCII.
3. *Web names*: strip a trailing web suffix (`.com`, `.Com`, `.co.in`; ≥ 4 word chars before the dot, suffix not a
   legal form) and `www.`; split concatenations by unigram Viterbi segmentation over a vocabulary counted from names
   (train + target records, no labels → `transductive = True`); 1/0 → l/o only if the variant is a known word.
4. *Initial runs*: `p l l c` → `pllc`, `m w jackson` → `mw jackson` (applied to both sides identically).

**Pre-registered variants** (`configs/exp/p2/`): A = all steps, replace mode (main); B = A in append mode (T04 asks
for both); C = A with only the learned maps (isolates cross-script); D = A without script folding (pooling gain).
Selection rule declared up front: best = highest full-density pair recall; ties (< 0.001) → the simpler variant.

**Evaluation protocol / anti-overfitting:**
- Full-density blocking: all 10.3M S2/S3 records, 10% of S1 as queries (`--qfrac 0.1`); the normalizer is fitted
  ONLY on true pairs of the other 90% of S1 (`fit_gt`) → the queries' pairs never inform the map.
  Script `exploration/p2/blk_eval_p2.py` = p1's protocol and metric code (imported) + recall on raw-defined subsets
  (non-Latin name / web name / empty address / letter runs) so every variant is judged on the same pairs.
- Map quality on held-out pairs: `exploration/p2/translit_map_report.py` (coverage + accuracy of mappings on the
  10% held-out S1 pairs; test coverage reported as a diagnostic only, never used for a decision).
- End-to-end: harness `val_v1@0.1` and `xc_India@0.1` for baseline vs best 2 variants (the map is fitted on the
  split's train side only; xc_India shows what happens when the map has no data for a country — the France proxy).
- Nothing is tuned on these evaluations; all variants tried are reported.
